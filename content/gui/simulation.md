This section explains how TAPAAL can be used to simulate the behavior of a Petri net.
In simulation mode, you can simulate the model by firing transitions and advancing time. This feature can help you discover simple errors in your model by allowing you to examine whether it behaves as intended.

{{% notice note %}}
TAPAAL does not currently implement native simulation of colored nets. Instead, it automatically unfolds the net.
{{% /notice %}}

You can activate Simulation Mode by selecting ![Simulation](/gui/simulation-indicator.png?classes=inline) from the toolbar or `Simulator - Simulation Mode` from the main menu. You can exit simulation mode at any point by clicking the button again.

Switching to simulation mode swaps the content of the side menu and removes all drawing features.
The available simulation features depend on the enabled modeling features.

![Simulation Mode](simulationmode-gui.png)

## Transition Firing

In the canvas, enabled transitions are marked in red: ![Enabled Transition](enabled-transition.png?classes=inline). You can fire any enabled transition by right-clicking it, after which the current state of the net is updated.

![Transition Firing](transitions-firring.gif)

The Transition Firing widget in the side menu shows a list of all enabled transitions across all components.
You can fire any transition from the list by double-clicking it or selecting it and pressing the `Fire` button.

![Enabled Transitions Widget](enabled-transitions.png)

## Simulation History

All transition firings and time delays are recorded in the Simulation History widget. This widget is also used to display counterexamples or traces generated by verification.

![Simulation history](simulation-history.png)

You can step backward or forward through the simulation history by selecting `Step backwards` or `Step forwards` from the Simulator menu.
For convenience, these actions are also directly accessible from the `Simulation Control` widget in the side menu ![Step back/forward](history-control.png?classes=inline), or by using the left and right arrow keys.
You can also jump directly to any state by selecting it from the list.

_Warning:_ If you step back in the trace history and fire a transition, it will overwrite the rest of the trace from that point onward.

## Time 
When time is enabled, you can perform time-delay actions as well as fire transitions. Like transition firings, time delays are recorded in the simulation history.

Time delays are performed using the Time delay button in the side menu. 

![Time Delay](time-delay.png)

You can enter a time delay directly in the text box next to the Time Delay button and perform the delay by clicking the button, or you can use the slider to select a suitable time delay. You can decrease or increase the slider range by pressing the `...` buttons next to the slider.

After performing a time delay, the ages of all tokens are updated accordingly. For places with two or fewer tokens, you can see the current age of each token (to one decimal place) directly. If a place contains more than two tokens, or if you need the full-precision age, move the mouse over the place:

![Token age](token-age.png)

Enabled transitions are highlighted in red. Transitions that can be fired after a given time delay (d-enabled) are highlighted in yellow: ![Delay Enabled Transition](denabled-transition.png?classes=inline). The Enabled Transitions widget also shows the time interval during which each transition is enabled.

![Enabled Transitions Timed](enabled-transitions-timed.png)

Firing a d-enabled transition by clicking it or selecting it from the Enabled Transitions widget performs a time delay and fires the transition. The time delay and transition firing are recorded in the Simulation History:

![Fire d-enabled](d-enabled.gif)

### Delay mode

By default, TAPAAL uses the minimum available delay needed to enable the transition. You can change this behavior by pressing `Settings` in the Enabled Transitions widget and selecting a different `Delay Mode`. By selecting manual delay, you will be prompted for a time delay when firing a transition.

The delay granularity affects the number of decimal places used in random simulation and determines the first value after a strict guard. A delay granularity of 0.01 would result in a delay of 5.01 for the guard `(5, inf)`.

![Delay mode](delay-mode.png)

### Token Selection

When firing a transition, TAPAAL selects the consumed tokens at random from the list of tokens that satisfy the arc guard. You can configure this behavior by setting the `Token Selection` mode in the Simulation Control widget.

![Token Selection](token-selection.png)

Token selection can be set to select tokens at random (the default), consume the youngest tokens first, consume the oldest tokens first, or use `manual` mode. In manual mode, a pop-up enables you to select the specific tokens to consume. _Note that the dialog is not shown if TAPAAL can determine that the resulting marking would be the same or that there is only one choice._

![Select tokens](select-token.gif)


## Automatic Random Simulation 

The simulator supports automatic random simulation. When enabled, it automatically selects a random transition to fire.
This can be useful for exploring or demonstrating the behavior of a net.

To enable random simulation, press the `Settings` button in the Enabled Transitions widget and check `Enable automatic random simulation`.
You can also configure the speed at which the simulation is performed. You can then close the settings menu and start the simulation by pressing the `simulate` button in the Enabled Transitions widget.

The automatic simulation can be stopped by pressing the `Stop` button in the Simulation Controls pop-up.
![Simulation Control](auto-simulation-control.png). You can also adjust the simulation speed using the "Set simulation speed:" slider. 

![Random Simulation](random-sim.gif)
